# Files

- [CBO Auth Step-Up API](cbo-auth-step-up-api.md) - Reusable step-up authentication endpoint (POST /cbo/auth/v2/step-up, EP-AUTH-01) used by CBO Wire Center to authorize wire release and designed for reuse by other high-risk client actions such as hold attestation.
- [CES Entitlements API (EP-CES-01)](ces-entitlements-api.md) - Synchronous REST interface exposed by the Commercial Entitlements Service — GET /ces/v2/users/{id}/entitlements — used by CBO Wire Center to authorize actions and filter search/activity results to a user's entitled accounts, and currently the blocking dependency (CBO-4473) for the PPH v1-to-v2 migration (CBO-4471).
- [ENS Notification API & TRS Event Catalog](ens-notification-api-trs-catalog.md) - Describes the Enterprise Notification Service (ENS) v3 notification/subscription APIs (EP-ENS-01..03) and the current Treasury (TRS) wire/ACH event catalog, including the explicit list of wire-lifecycle notifications (network acceptance, gpi ACCC, returns, held-wire client action) that do not yet exist.
- [Fedwire Network Acknowledgment Topics](fedwire-network-ack-topics.md) - net.fedwire.ack.v1 and net.fedwire.inbound.v1: Kafka topics published by the Fedwire Funds Connector carrying OMAD and the Federal Reserve's settlement timestamp plus inbound value messages, consumed today only by PPH, with a TDIP ingestion (TDA-2210) and a PPH v2 settlement object (PPH-2207) both parked in backlog.
- [Interface: gpi Tracker Batch Snapshot Feed](gpi-tracker-batch-feed.md) - The 4-hourly batch integration by which the Swift Alliance & gpi Connector (GPI-C) pulls Swift Tracker API updates into GPI_TRACKER_SNAPSHOT, the Swift Tracker API's 250,000-call monthly quota, why per-payment client lookups would blow that contract ~7x, and the declined 2-hour frequency change (PNG-1544).
- [HMS Hold API & Hold Events](hms-hold-api.md) - Internal-only API surface of the Hold Management Service (EP-HMS-01/02 and event topic EV-HMS-01 risk.hold.events.v1) — callable only by the Investigations Workbench and PPH's legacy description sync, with no client-facing hold interface in production and the client-safe facade proposal FCT-1893 deprioritized.
- [PPH Kafka Lifecycle Event Topics](pph-lifecycle-event-topics.md) - EV-PPH-01 pay.wire.lifecycle.v2 and EV-PPH-02 pay.ach.lifecycle.v1: PRISM Payments Hub's Kafka payment-lifecycle topics, their Avro payload, 7-day retention, Jira-based consumer ACL onboarding, and what is (ISO return reasons since 2026-08) and is not (hold reasons) published.
- [PPH v1 Wire Status API (deprecated)](pph-v1-wire-status-api.md) - The legacy synchronous REST surface of PRISM Payments Hub (EP-PPH-01/02/03) that CBO Wire Center still depends on for wire submission, listing, and status — including the PROCESSED status collapse and the holdReasonDesc HMS free-text leak (FCT-2004) — rate-limited to 20 TPS shared and scheduled for sunset 2027-03-31 with no extensions.
- [PPH v2 Payments API](pph-v2-payments-api.md) - Current (GA 2025-10) REST surface of PRISM Payments Hub for payment detail, search, state history, and submission — exposing lifecycleState, rail-aware identifiers (including UETR and OMAD), and hold presence only — plus the two open backlog gaps (settlement object, beneficiary-name search) tracked against it.
- [CBO Status Projection Service (SPS) Read Model API](sps-read-model-api.md) - /cbo/sps/v1, the Kafka-consumer-to-Postgres read-model API behind CNB's reference event-driven channel status pattern (ADR-PAY-019); today configured for ACH only (pay.ach.lifecycle.v1), with wire support requiring a new mapping module and a consumer ACL on pay.wire.lifecycle.v2.
- [TDIP Insights API](tdip-insights-api.md) - Versioned, entitlement-aware REST serving layer of the Treasury Data & Insights Platform through which all client-facing predictions and statistics must be published, per ADR-PAY-026; today only the cash-forecast endpoint (EP-TDIP-01) is generally available.
