## Overview

`cbo_wire_events` is a dataset cataloged in the Treasury Data & Insights Platform (TDIP) Payments domain data catalog. It captures clickstream activity generated by the **Wire Center** module of [Crestline Business Online (CBO)](../systems/cbo-wire-center.md), CNB's commercial digital banking portal. Unlike most other Payments-domain datasets in the catalog, which are sourced from payment-processing systems of record (Prism Payments Hub, GPI Tracker, Core Deposit Platform), `cbo_wire_events` is sourced from the CBO channel's own usage telemetry — i.e., in-portal user interaction events rather than payment transaction records.

|---|---|

| Refresh | Hourly |
| History retained | 13 months |
| Classification | Internal |

## Classification and ownership

`cbo_wire_events` carries an **Internal** classification — the lightest classification tier among the Payments domain datasets in the TDIP catalog. By contrast, sibling datasets such as `pay_wire_txn_hist`, `gpi_tracker_events`, and `client_hierarchy` are classified Confidential - Client, and `dda_txn_history` is Restricted - Client Confidential. The lighter classification is consistent with the dataset's content: it records portal navigation/interaction events rather than client wire payment details, account numbers, or counterparty data.

Marcus Chen is recorded as the sole data owner/steward for `cbo_wire_events` in the catalog (other Payments-domain datasets list a business data owner alongside a TDIP data engineering steward, e.g., Carlos Mendes). Chen is also the Product Owner for the CBO Wire Center squad and the business owner of record for the CBO Wire Center module (SYS-CBO) and related CBO platform systems (SYS-CBO-SPS, SYS-CES) in the PTT system ownership register, which aligns product ownership of the source channel with ownership of its derived clickstream dataset.

## Relationship to the Wire Center module

[CBO Wire Center](../systems/cbo-wire-center.md) is the production system that generates the underlying click/usage events. Wire Center provides domestic (Fedwire) and international (Swift) wire initiation, templates, dual approval, release with step-up authentication, a wire activity list, wire detail view, CSV export, and confirmation PDF download — all surfaces that would plausibly emit the clickstream events aggregated into `cbo_wire_events` (e.g., page views, "Refresh status" clicks, list and export actions). The current-state architecture document for Wire Center records trailing-90-day usage figures that characterize the scale of this instrumented activity: ~1.4 million Wire Center page views per month and ~310,000 "Refresh status" clicks per month, across roughly 9,800 entitled client companies and ~41,000 active 90-day users.

The Wire Center architecture document does not itself name `cbo_wire_events` or describe a specific clickstream pipeline/schema; the dataset's existence and refresh cadence are established only by the TDIP data catalog entry. Readers needing the event schema, emission mechanism, or pipeline topology that produces `cbo_wire_events` should treat this as an open gap pending a data engineering specification from the TDIP/CBO teams.

## Relationship to TDIP and the Insights API

[Treasury Data & Insights Platform (TDIP)](../systems/treasury-data-insights-platform.md) is the platform of record for `cbo_wire_events`: TDIP runs on Snowflake (Enterprise, US-East) with dbt transformations, a Feast feature store, Amazon SageMaker for model training/scoring, and an Insights API serving layer, and governs dataset access through Collibra.

Within the current catalog, `cbo_wire_events` is **not** listed as a source for any of the three published feature tables (`wire_corridor_stats_daily`, `beneficiary_behavior_profile`, `client_wire_history_features`), which are instead derived from `pay_wire_txn_hist`, `gpi_tracker_events`, and `dda_txn_history`. It is also not consumed by the one GA Insights API endpoint (`GET /tdip/insights/v1/cash-forecast/{clientId}`). As of the current catalog edition, `cbo_wire_events` therefore has no documented downstream feature-table or Insights API consumer — it is cataloged but not yet feeding a published analytical product.

## Freshness and known gaps

- **Hourly refresh, 13-month rolling history.** This is a tighter refresh cadence than `dda_txn_history` and `client_hierarchy` (both Daily) and is on par with `pay_wire_txn_hist` (Hourly). It differs from `gpi_tracker_events`, which refreshes nightly until the TDA-2188 initiative moves it to hourly (targeted 2026-11).
- **No real-time serving.** The TDIP catalog's known-gaps section states there is no real-time (sub-minute) serving for wire-related data generally; minimum freshness across the Payments domain, including `cbo_wire_events`, is hourly.
- **Access governance.** Dataset access across TDIP is governed in Collibra; Restricted-classified datasets require Privacy Office approval (15 business-day SLA). `cbo_wire_events`'s Internal classification places it outside that Restricted-tier approval gate, though it remains subject to standard Collibra-governed access control.
